# SHEAR CUDA CTA 线程利用与调度优化方案

日期：2026-11-03。

**状态：优化清单与实验设计。** 本次只编写方案，没有修改 CUDA 实现或新增性能测量。源码中的实验实现、宏开关、设备正确性与实测收益分别记录，不根据“存在代码”判断“已经验证通过”。

本文件与 [SHEAR CUDA 四项优化与逐项测试方案](./SHEAR_CUDA四项优化与逐项测试方案.md) 配套使用：原文保留 O1～O4 的详细设计，本文件列全两个 CTA 的优化环节，并展开其余步骤。已有的 [SHEAR CUDA 优化记录](./SHEAR_CUDA优化记录.md) 中的量化 kernel 线程适配属于另一个实验范围。

## 1. 对象与判断标准

对象是 persistent kernel 中的分区 worker CTA 与候选 TopK worker CTA，以通用 dense SQ8/WMMA 路径为主。两类 CTA 在当前主路径都使用 256 个线程，即 8 个 warp；线程 0 领取任务并更新共享状态，后续线程分工随阶段变化。实际角色还可能通过帮助执行切换，不能只看 block 的初始分类。

不把 D0 的 partial/merge kernel、SQ8 量化 kernel、DP4A、TF32、SQ4、RabitQ、D96/K2 专用路径混入同一组归因实验。改动影响共用结构时，对受影响分支补做回归测试。

需要分别记录三类问题：

- **线程无有效任务：** 半 warp 后处理、领取不足、尾块或小任务。
- **执行但产出较少：** 补零矩阵、重复数据准备、额外中转。
- **等待推进：** 行锁、队列、阶段切换、同步或数据依赖。

“某循环最多 16/256 个线程搬运”只是该段源码的线程分工，不是整个 kernel 的实测利用率。最终以同工作量下的有效吞吐、阶段时间和完整构建时间判断，不能以活跃线程数增加作为唯一成功标准。

### 2.1 主流程中的位置

```text
领取 partition 节点/ticket                         P6、S1
    ↓
大分区距离：加载 A/B → WMMA → 读 C → 维护 top-r    G1～G5
    ↓
COUNT 提交 → EMIT 偏移 → SCATTER → PUBLISH          P2 → P3 → P1 → P4
    ↓                         小节点路径另看 P5
领取 leaf task、分配源行和候选列                    C2、C3、S1
    ↓
叶内距离：加载 A/B → WMMA → 读 C → 维护 TopK       G1～G5、C1
    ↓
直接写出，或 staged 局部结果归并                    C4
```

G4 的双线程距离恢复不自动使 TopK 插入并行；G5 才进一步改变候选维护。G3 传输的是量化向量维度数据，P1 搬运的是分区成员 ID。原方案中覆盖小 leaf、尾块和 staged 的测试，也不代表已实现 C2 或 C4。

## 3. 分区 CTA 的新增方案

<a id="p1"></a>

### P1：SCATTER 整批成员并行搬运

**概要。** 当前领取一批 tile 后，仍逐个处理每个 16 行块。每轮搬运最多 16 个线程进入有效循环，并经过多次 CTA 同步。目标是把本批成员交给更多线程，同时减少写入竞争。

**独立变体。**

1. P1-A：先保持写入原子操作与语义，只把整批行区间展开给 CTA 线程；可采用 `row = batch_begin + threadIdx.x` 的跨步方式。不能只扩大循环范围而继续使用只能容纳 16 行的临时数组。
2. P1-B：在独立基线上尝试按子分区聚合写入数量，一次申请一段输出区间，再由线程写入；与 A 分别测量后再组合。

**正确性。** 比较每个父任务、leader 对应的成员多重集与复制次数；保留 fanout 重叠语义。检查 child offset/write cursor、尾块、容量失败、重试 generation 变化和阶段完成计数。只有本批数据确实写完，才能计入 SCATTER_DONE 并推进 PUBLISH。

**边界与指标。** 配置 batch 1/8，覆盖实际领取 1/2/3/8 个 tile，以及 1、15、16、17、127、128 个有效成员；测试均匀与高度集中的归属。记录 SCATTER 时间、成员/s、原子次数、屏障次数、scratch 开销和整个分区阶段时间。

**取舍。** 更大的临时缓冲可能增加 shared memory；批量分发会改变物理排列。排列可规范化比较，但不能丢失成员、重复写入或改变归属。

<a id="p2"></a>

### P2：COUNT 计数提交的线程分配与原子聚合

**概要。** WMMA 计算完成后，当前按成员分配线程，在线程内遍历 local_fanout 并对 child count 原子累加。batch-8 满批最多 128 个成员，因此该提交循环最多由 128 个线程承担。

**独立变体。** P2-A 将有效的“成员×fanout”项展开成线性工作；P2-B 单独测试 warp/CTA 内聚合同一 child 的增量，再减少全局原子提交次数。不要为填满线程而增加原本不存在的归属项。

**正确性。** 输入冻结为同一份 `large_best_slots`，逐 child 比较计数；检查总计数等于有效归属数。无效 slot、错误标志和容量检查沿用原语义。

**边界与指标。** fanout=1/2/4、短尾块、全部集中到少数 child 及均匀分布。记录计数提交时间、全局原子次数、聚合指令和临时状态成本。fanout=1 或分布分散时，额外聚合未必有收益。

<a id="p3"></a>

### P3：EMIT 偏移计算按规模选择实现

**概要。** 获得 EMIT 处理权的 CTA 由线程 0 顺序生成 child offsets、清零写游标，并统计非空 child 和最大 child。目标是评估较大 child 数时的协作扫描。

**方案。** 保留小规模串行实现，独立测试并行 exclusive scan 与 count/max 归约。偏移必须仍对应同一 child 顺序。阶段锁、generation 复核、是否有效分裂、重试/平衡回退等控制逻辑单独保留。

**正确性。** 比较 offsets、write cursor、总归属数、nonempty 与 max_child，以及是否进入相同重试/回退分支。覆盖空 child、单个非空 child、16/17/32/128 个 child、容量恰好到界和超界。

**指标与取舍。** 记录 EMIT 时间和后续任务就绪时间，同时计入 shared 存储与同步。单线程比例低不代表耗时高；较少 child 的串行路径可能更便宜。

<a id="p4"></a>

### P4：PUBLISH 批量预留与并行填写描述符

**概要。** 当前发布者遍历 child，决定发布 leaf 还是 partition，并填写队列和元数据。目标是分摊大量描述符准备工作，减少细碎队列操作。

**方案。** 先保持任务划分决策不变，计算待发布的任务数并批量预留槽位；再让线程填写互不重叠的描述符/成员区间。明确区分“槽位已预留”和“任务可消费”。描述符与数据准备完成后，才按原协议发布 ready。

**正确性。** 检查队列容量、ready 可见性、active 计数与完成检测；验证消费者不会读取未写完的任务。覆盖仅 leaf、仅 partition、混合 child、空 child、达到 max_depth、队列临界容量和错误退出。检查 leaf 源行×候选列的任务展开是否完整。

**指标与取舍。** 记录发布阶段时间、原子与 fence 次数、首个 leaf 就绪时间及消费者等待。更大的批量可能推迟首个可执行任务；不能只测生产者自身更快。

<a id="p5"></a>

### P5：小节点合批或 warp 级处理

**概要。** 当前部分小节点由线程 0 调用节点处理函数，其他线程等待。目标是评估多个独立小节点共用 CTA，或让一个 warp 协作处理一个节点。

**方案。** 首轮只改变执行组织，保留成员、leader 选择、随机种子、深度与终止规则。分别测试节点合批与 warp 级实现；每个任务使用独立的 metadata/scratch 区域。不能只把线程 0 的函数调用复制到多个线程。

**正确性。** 比较规范化后的父子任务成员多重集、叶块候选和错误标志。覆盖大量极小节点、单个小节点、不同深度与 fanout 混合、重复向量和距离接近的点。

**指标与取舍。** 记录每节点处理时间、任务/s、发布成本和 GPU 总时间。不同节点的循环长度与 leader 集合可能造成分歧；分批本身也有状态管理成本。

**范围限制。** 合并节点的执行批次不等于合并其算法上的叶块。改变 leaf 边界会改变点对集合与图质量，属于另一项算法实验。

<a id="p6"></a>

### P6：ticket 领取与尾部补充工作

**概要。** 当前以 CTA 为单位领取 tile 范围，再把工作交给 warp。剩余 tile 不足时，有效 warp 数下降。目标是减少短批和执行尾部的无工作等待。

**方案。** P6-A 研究按剩余工作调整领取粒度；P6-B 在单独实验中研究更细粒度的补充任务。冻结实际 tile 集合，不顺带改变 leader 选择、fanout、距离执行器或叶块边界。

**正确性。** 检查每个 ticket 恰好执行一次，COUNT_DONE/SCATTER_DONE 统计的是已完成工作，不能以“全部领取”替代“全部完成”。验证 generation 更新、阶段切换、错误与 watchdog 路径。

**边界与指标。** 覆盖 1/3/7/8/9 个 tile、大量小任务和耗时不均衡的任务。记录领取次数、每次实际块数、有效 warp 分布、尾部完成时间和整个 kernel 时间。

**同步限制。** 已有 O3-A 共享 B 特化要求部分无源行 warp 也参加 CTA 屏障。更细粒度补充不能让不同 warp 随意进入不同次数的 CTA 同步。

## 4. 候选计算 CTA 的新增方案

C1 的详细方案继续使用原文 O2：先评估消除中转，再决定是否做小 k 专用化。不能把最终输出 k 与精排前 survivor 数合并为一个容量，也不能从声明数组大小直接推算真实寄存器浪费。

<a id="c2"></a>

### C2：源行任务划分、小 leaf 与无有效源行

**概要。** 通用执行器每 warp 覆盖 16 个源点，一轮 CTA 行带覆盖 128 个源点。任务较小时，部分 warp 没有有效源行，仍可能进行补零与矩阵准备。

**独立变体。** C2-A 尝试按形状选择 block/warp 数；C2-B 尝试多个小任务合批；C2-C 单独研究跳过无有效源行的矩阵工作。先保持每条源行的候选范围和计算语义不变。

**正确性。** 检查每个叶块输出行恰好处理一次；同一全局点在不同叶块出现仍属于不同的输出行。覆盖 1/15/16/17/19/127/128/129 个源行、候选列尾块、自身候选和无效填充。

**同步限制。** 使用共享 B 的特化中，无有效源行 warp 也可能需要加载公共数据并经过 CTA 屏障。只能在满足同步约束的位置屏蔽计算，不能直接按 `active_row=false` 让整个 warp 提前返回。修改 blockDim 还需检查 scratch、清零循环和所有固定 8 warp 的假设。

**指标与取舍。** 记录有效源行/CTA、真实点对/执行矩阵元素、任务/s、shared/寄存器资源和完整 leaf 时间。合批不同 leaf 时必须保留各自候选边界；不能把不同 leaf 拼成互相比较的一个大 leaf。

<a id="c3"></a>

### C3：row-owned 与 staged 列切分策略

**概要。** row-owned 让一个任务扫描其源行的完整候选范围；staged 增加候选列分块，提供更多任务，也增加重复加载和归并。目标是根据真实任务形状与供给选择切分。

**方案。** 先固定相同 leaf，分别强制两种现有模式比较；再独立测试仅基于 leaf 行数、维度、k 的静态选择。依赖实时队列深度的动态选择列为后续变体，避免一开始同时改变太多条件。

**正确性。** 验证每个有效点对的覆盖、源行输出数量、排除自身、重复候选与 tie-breaking。即使点对集合相同，插入和归并顺序改变也可能在距离容差附近影响 ID；需要对抗用例，不直接假设等价。

**边界与指标。** leaf 行数 127/128/129、511/512/513 以及较大 leaf，D=96/128/256/1024，k=2/4；同时检查实际专用路径路由。记录列任务数、重复读取、锁等待、队列供给和完整 leaf 时间。

**取舍。** 任务不足时额外切分可能有帮助；任务已充足时增加切分可能只增加成本。与 C4 独立测量。

<a id="c4"></a>

### C4：staged 局部结果归并与行锁竞争

**概要。** 同一输出行的多个列任务通过行锁合并局部 TopK。线程可能在 CAS 轮询时活跃，却没有推进计算。目标是减少竞争和重复合并。

**独立变体。** C4-A 为每份局部结果使用独立输出区，第二阶段按源行归并；C4-B 研究由指定归并者在结果就绪后完成归并。先保留局部候选生成方式，与 C3 的列任务划分分别比较。

**正确性。** 完成计数/ready 必须覆盖所有列任务，禁止提前消费或覆盖仍被使用的结果。测试多任务同时完成、单个慢任务、重复候选、距离容差链及错误退出。若不能保持原候选处理语义，明确作为算法变体，不归类为纯执行优化。

**指标与取舍。** 比较行锁轮询、归并次数和时间，计入额外局部结果显存、全局访存、第二阶段 launch 或等待开销。消除自旋不保证总时间下降；row-owned 原本无此类跨列归并时，不应额外引入归并步骤。

## 5. 两类 CTA 共用的计算方案

本节保存全部 G 编号，详细改动、伪代码和验证以 [原四项方案](./SHEAR_CUDA四项优化与逐项测试方案.md) 为准。

| 编号 | 方案与作用步骤 | 必须单独检查的边界 |
|---|---|---|
| G1 = O1 | C tile 按与消费线程匹配的布局写入/读取 | 所有消费者使用同一逻辑地址；比较完整整数内积；布局变化不等于已证明 bank conflict 收益 |
| G2 = O3-A | 多个 warp 共用 B 的 shared 缓冲，保留各自 A 与 accumulator | CTA 屏障、无源行 warp、公共元数据和提前退出；硬件缓存可能已吸收部分重复请求 |
| G3 = O3-B | 独立尝试较宽维度搬运，再用多个 K=16 子块消费 | leading dimension、对齐、补零、尾部和 scratch 增长；单改步长不保证减少指令 |
| G4 = O4-A | 两个 lane 恢复同一源行的不同候选列距离，再保持原顺序插入 | 恢复距离阶段使用 32 lane，TopK 插入仍由原 owner 执行；计入中转和同步成本 |
| G5 = O4-B/C | 双 lane 局部 TopK 后归并，或每 warp 处理两组源行 | 非传递距离容差、ID 顺序、源行恰好覆盖一次，以及任务行数/CTA 配置匹配 |

G2/G3 不自动消除目标块变化时 A 的重新加载。完整缓存 A、异步预取或双缓冲属于额外变体，先记录资源和同步成本，不混入现有单项归因。

## 6. 两类 CTA 的协同调度

<a id="s1"></a>

### S1：角色配额、互助和任务顺序

**概要。** 分区 CTA 产生 leaf 工作，候选 CTA 消费；已有帮助执行机制只能在合适阶段、存在可领取工作时推进。目标是减少早期供给不足与末尾长任务等待。

**独立变体。** S1-A 固定任务，比较不同合法的 partition/topk worker 比例；S1-B 独立比较帮助执行的触发时机；S1-C 研究任务顺序，比较优先生成 leaf 与优先推进大分区。不要同时修改任务边界或增加距离计算量来填满 GPU。

**正确性。** 复核跨 CTA 发布与完成协议：队列暂时空、工作已被领取、生产结束、候选消费结束是不同状态。所有角色都要正确处理 overflow、generation 和 watchdog。保持 launch 的驻留资源约束及初始化等待协议，不能无限增加 CTA 数来制造并行。

**指标与取舍。** 记录首次 leaf 就绪时间、队列深度、空轮询、有效帮助工作量、最后一批任务完成时间、完整子树 CUDA event 时间。区分 kernel 内等待与 H2D/主机处理造成的子树之间 GPU 空档。帮助执行、角色切换和轮询策略本身也有成本。

## 7. 逐项验证与执行顺序

### 7.1 基线与状态

沿用原方案的环境、编译特化、冻结输入、设备正确性、计时和记录规范。本清单不创建新的可执行开关或 benchmark harness，不把上述变体名称当成现有命令参数。

保存实际工作区补丁、代码哈希、GPU/驱动/工具信息和输入清单。若旧方案记录的性能计数器权限限制仍存在，先使用 CUDA event、正确性测试和实际加载 kernel 的资源属性；未采集的指标明确留空，不从时间变化反推硬件现象。

状态分开记录：`待实现`、`已有实验代码/待核对路由`、`正确性通过`、`无稳定收益`、`特定形状有收益`、`端到端验证通过`。本次文档更新不替任何实现修改这些状态。

### 7.2 每一项的验证层次

1. 检查目标函数和实际编译分支，准备独立变体以及同输入 B0。
2. 用独立 oracle 比较内积、距离、ID、count、offset 或成员多重集，按对应步骤选择检查对象。
3. 覆盖源/目标尾块、极端归属、重复/近似相等距离、容量边界、失败与退出。
4. 改动 shared、ready、锁、发布或阶段切换时，补充并发测试和可用的 sanitizer 检查。
5. 固定同一批任务测算子或阶段，再测完整 persistent kernel。
6. 同一构图参数测整体时间与图质量，记录候选/点对工作量、输出规模和 recall/QPS。

阶段内部多 CTA 的 `clock64()` 累计值可能重叠，不能直接相加解释为 GPU wall time。诊断计数、sanitizer 与 profiler 运行单独记录，不混进正式性能样本。

### 7.3 实验组织

- O1～O4 继续按原文顺序做独立实验，不因补充清单改变原有编号。
- 新增项可从 P1、C2 的形状诊断开始，继而分别研究 P2、P3、P4、C3、C4；P5、P6、S1 涉及更广的调度与协议，使用独立变体。
- 这表示实验拆分建议，不表示已测得的瓶颈排名。若基线显示其他阶段占主要时间，调整研究顺序并记录理由。
- 每一项首先对照同一原始 B0。只有独立正确性与收益明确后，再建立组合并同时对比 B0 和相关单项。
- C2+G2、P6+G2 重点复核同步；C3+C4、G5+C4 重点复核结果顺序和归并；P1+P4 重点复核发布前数据完成。

若复用正式 TESSA 实验，使用其 [运行手册](../docs/runbooks/tessa_progressive_ablation.md) 和现有命令生成协议。小型验证与正式长跑分别组织；本次没有执行这些实验。
